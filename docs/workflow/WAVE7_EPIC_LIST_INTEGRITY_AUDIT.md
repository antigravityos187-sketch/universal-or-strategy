## Root Cause: How Did This Happen?

### Where duplication was introduced

The pattern is unambiguous:
- **W7-001 to W7-080**: All unique. First 80 epics were clean.
- **W7-081**: First real duplicate appears (`AuditMaster_HandleNakedPosition` = copy of W7-031)
- **W7-082 to W7-161**: 46 of these 80 epics are duplicates or blanks

The epic list was generated by `complexity_audit.py` scanning `src/*.cs` twice — once to build
the original hotspot list (W7-001..080), and a second time when additional epics were added to
reach 161. **The second pass did not deduplicate against the first pass.**

### The blank method_name cluster

W7-007 had a blank `method_name` and `source_file` in the original list. W7-041, 054, 057, 070,
092, etc. all resolve back to W7-007 as their "first seen" blank. These epics had CYC data from
`complexity_audit.py` but the method name was not captured correctly (likely a regex failure in the
original list-generation script, or the method was nested/partial at the time of scan).

### Why weren't duplicates caught earlier?

1. **Phase 0-4 never validated uniqueness** — they checked artifact existence and content, not whether the method target was the same as another epic.
2. **Phase 5 used `phase_5.status=completed` as truth** — once a duplicate epic's manifest was stamped `completed`, no check asked "but did the source actually change?"
3. **`wave7_batch_audit.py`** had no cross-epic deduplification check. It audited each epic in isolation.
4. **`precompute_wave7_graph.py`** ingested the epic list verbatim with no dedup guard.

## Hardening Protocol — Preventing This in Future Waves

### Fix 1: `precompute_wave7_graph.py` — add dedup guard (IMMEDIATE)

The precompute script must reject a source list that contains duplicate `(method_name, source_file)` pairs before writing any `precomputed.json`.

```python
# In precompute_wave7_graph.py, after load_epic_list():
seen_pairs = {}
for epic in epics:
    key = (epic['method_name'], epic['source_file'])
    if epic['method_name'] and epic['source_file'] and key in seen_pairs:
        print(f"[ERROR] DUPLICATE: {epic['epic_id']} is a copy of {seen_pairs[key]}")
        print(f"        method={epic['method_name']} file={epic['source_file']}")
        sys.exit(1)   # HARD FAIL — fix the list before running
    seen_pairs[key] = epic['epic_id']
```

### Fix 2: `scripts/validate_epic_list.py` — new standalone validator

Run before every wave start. Checks:
- No blank `method_name`
- No blank `source_file`
- No duplicate `(method_name, source_file)` pairs
- All source files exist in `src/`
- All methods resolve in `complexity_audit.py` output

### Fix 3: Wave kickoff checklist (in AGENTS.md + SOP)

**Before spawning Phase 0**, the Tier-1 orchestrator MUST:
```
1. Run: python3 scripts/validate_epic_list.py
   → Must exit 0 (zero duplicates, zero blanks)
2. Run: python3 scripts/precompute_wave7_graph.py
   → Must exit 0 (triggers dedup guard above)
3. Confirm: total unique (method, file) pairs == total epics
```

If validation fails → **HALT. Fix the epic list. Do not proceed.**

### Fix 4: Phase 0 worker adds dedup check to hotspot analysis

The `v12-phase0-hotspot` worker should check if its assigned `method_name` matches
another epic's method and flag it as `is_duplicate: true` in `precomputed.json`.

### Fix 5: Phase 5 verifier checks for duplicate inheritance

When `v12-phase5-v-verify` sees a failing gate, it should check if a sibling epic
(same method+file) has already been completed. If yes → mark as inherited, not fabricated.

### Fix 6: `wave7_batch_audit.py` cross-epic consistency check

Add a new `--check-dupes` flag that reports any epic pairs sharing method+file and
flags those where primary=PASS and secondary=FAIL (should be free ride, not failure).
